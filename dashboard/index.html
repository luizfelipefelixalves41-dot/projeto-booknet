O CONTEXTO

Organizar a biblioteca.
Entender a distribuição.

O problema
Uma biblioteca universitária precisa organizar o acervo, identificar seus usuários e acompanhar a circulação dos exemplares.
Nosso objetivo
Planejar esse gerenciamento em componentes com responsabilidades claras, aplicando os conceitos de Sistemas Distribuídos.

Para quem estamos construindo?

02 / A ESTRUTURA

Arquitetura do sistema

Cinco componentes. Uma responsabilidade para cada parte.

Abrir diagrama SVG ↗

Por que uma arquitetura distribuída?

O BookNet prevê componentes independentes para usuários, catálogo e empréstimos, que se comunicarão pela rede e poderão evoluir separadamente. Essa organização permite estudar comunicação entre processos, concorrência, disponibilidade, escalabilidade e tolerância a falhas. Uma falha em um serviço não precisa interromper todas as funcionalidades.

Para uma biblioteca pequena, uma aplicação monolítica poderia ser suficiente. Neste projeto, a arquitetura distribuída foi escolhida principalmente para permitir a aplicação prática dos conceitos estudados na disciplina.

05 / OS DESAFIOS

Quando algo dá errado

Três situações para estudar ao distribuir as responsabilidades.

CENÁRIOS PARA ANÁLISE
01

Serviço indisponível

Cenário
O Serviço de Empréstimos fica offline.
Consequência
O aluno ainda poderia consultar o catálogo, mas não conseguiria realizar empréstimos.
DisponibilidadeTolerância a falhas
02

Concorrência entre usuários

Cenário
Dois usuários tentam pegar o mesmo exemplar ao mesmo tempo.
Consequência
Sem controle adequado, poderiam ser registrados dois empréstimos para um único exemplar.
ConcorrênciaConsistência
03

Falha de comunicação entre serviços

Cenário
Empréstimos consulta Catálogo, mas a rede falha ou a resposta não chega.
Consequência
Não é possível confirmar se o exemplar está disponível para empréstimo.
Rede / timeoutComunicação distribuída

Na V0, esses cenários estão documentados. A investigação e a implementação de soluções fazem parte da evolução do projeto.
